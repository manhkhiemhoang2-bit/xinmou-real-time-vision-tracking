## ③ 残留边界（1 个像素，已点名为例外 —— 是**已知边界**，不是未知缺陷）

**确切触发条件**：某拍的**最右像素**要用"**下一拍的首像素**"（`w_bot_4 = w_w0`，
与 `win3x3_96 §5` 的 `w_bot_4 = w_g0` 同法），而该拍之后 `I_tvalid` **连续拉低 ≥2 拍**
⇒ 该像素在"输出必须锁存"的那一拍之后才到 ⇒ latency 3 下**差一拍、取不到**。
实测样本：F3 孤立点在 (4,16)（正好落在拍边界），失配 `f3 y4 col15` 1 个像素；
连带 A9 探针 1 拍（f3 row4 grp4：ref_ins=1 / dut_ins=0 —— 错的 e3 把 inside 带错一拍，
像素仍对得上）。

**四条证据**：
1. 同激励下把前瞻恒 0（M5old），dump 与基线**逐字节相同** ⇒ 该前瞻"只在唯一一处起作用、
   而那一处本来就是气泡"，不是接线错；
2. 保真模型四口径扫描（气泡 1/2/3 拍 × 前瞻可得性）：2 拍下 现在=1 / +1=1 / **+2=0** / 上界=0
   ⇒ 唯一失配就是"前瞻拿不到"；要 0 必须允许**等 2 拍**，而 latency 3 最多等 **1 拍**；
3. **真 RTL 实测 BUB_SKIP=1（行中连续停 1 拍）→ TB PASS、10500 次检查 0 失配**
   ⇒ ≤1 拍完全正确，只有 ≥2 拍才触发；
4. 模型对当前 RTL dump **13 字段 × 704 行逐行相同（FIDELITY-OK）**。

**为什么真实链路大概率不触发**：本项目停顿来源是行/帧消隐，都发生在**行边界**，
而模块的行计数器本身被 `I_tvalid` 门控 ⇒ 行中不会出现连续 ≥2 拍空洞。
**需要在 M7（`alg_top` 集成后）全尺寸回归里核**：若实际流出现行中 ≥2 拍停，
该像素会复现（届时按下面备选处理）。

**已评估的备选（你已拍板选 A）**：

| 方案 | 代价 | 结果 |
|---|---|---|
| **A 接受该边界 + 坐标级点名例外**（本轮采用） | 0 | 小尺寸 1 像素（已点名）/ HD 0 |
| B `O_tdata` 加气泡恢复旁路 mux（组合输出） | 96 个 2:1 mux + 装配组合路径直连输出引脚（alg 臂 WNS 仅 750 ps，不值得） | 0（仅模型口径，未实现） |

## ④ 集成结论（接 M7 / 对齐 `alg_top` 延迟表照这个用）

1. **行位移**：**输出拍 y 承载输入第 y−1 行的填充结果（整体晚一行）** —— 与 `win3x3_96.v`
   （r0/r1/r2 = y−2/y−1/y、中心 y−1）同口径，也与 `check_alg_top_full.py` 的 `_shift1()` 一致；
   `alg_top` 里本档位按"整体下移一行"对齐。
2. **掩蔽**：模块内掩蔽 **3 行**（= 参考 2 行 + 位移 1）+ 每行第 0 拍：
   `w_win_valid = (r_y >= 3) && (r_x != 0) && !r_tuser`。**下游不要再叠行掩蔽。**
3. **时序/协议**：O_tvalid/tlast/tuser/tdata 与 I_* 同拍、延迟 **3** 拍；`I_tready` 直通不反压。
4. **契约建议**：`I_tvalid` 行中连续拉低 **≤1 拍**（≥2 拍时 §③ 那个像素算不出来）。
5. **资源**：未跑 TD（本轮不做）；删掉 r_bl2/r_bl3 后本级只少不多，2 条行缓存不变。
