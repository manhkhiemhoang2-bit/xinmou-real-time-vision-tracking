### 2.4 阈值选值的**实测**依据（`sim\_m7_thresh_probe.py`）

口径（三处写死同一份：`alg_top.v` §5d / `gen_stim_top_full.RF_TH` / 本报告）：
**白 ⟺ 三字节都 ≥ `RF_TH`（默认 128）**，其余一律黑。

| 几何 | 非边缘像素 min(R,G,B) 最大 | 边缘像素 min(R,G,B) 最小 | T=121..128 | T=8 | T=129 | T=255 |
|---|---|---|---|---|---|---|
| 160×64（帧 0..2） | 12 | 128 | **与 edge 掩码 0 失配** | 10,719 错 | 3,049 错 | 7,757 错（前景 0） |
| 1280×720（帧 0） | 120 | 128 | **0 失配**（163,777 前景） | — | 28,575 错 | 前景 0 |

* **128 = "不漏边缘"的最大阈值**：提亮后 `out_min = min(min(src)+K, 255) ≥ K = 128` 恒成立
  ⇒ 阈值 ≤ 128 时真边缘一个不漏；129 就漏 28,575 个。
* 非边缘像素 `out = src` 原样，实测 min 通道 ≤ 120 < 128 ⇒ 128 时不误判。
* 于是"三字节都 ≥ 128"在**本套激励**上逐像素等价于 Sobel edge 掩码（8 帧全部 0 失配，
  判据 M④ 每次跑都复验这一条）。
* `"三字节全 0xFF"`（254/255 口径）实测前景 **0** —— 这就是任务书说的"填不出东西"。

## ③ 集成的四处改动（都在 `alg_top.v`，M7 支路，未动任何已验收模块）

1. **档位**：`localparam MODE_REGIONFILL = 3'd7`；按键循环上限 `MODE_MOTION → MODE_REGIONFILL`；
   mux 加一支（数据+控制都取 `u_rf` 自己的）；`O_mode` 因此能出 7（判据 D：f7=[7]）。
2. **输入源**：`M3 的边缘流 → 硬阈值（`RF_TH`，见 2.4）→ u_rf`。
   阈值级是**纯组合**、不占延迟 ⇒ u_rf 的"延迟 3 拍"原样成立（累计 **4+3=7**）。
   输入还**与 `r_mask_d` 相与**（理由见 ④，这是本次唯一的非预期发现）。
3. **延迟**：M7 = **8 拍**（7 + 本级输出寄存器），M0..M6 仍是冻结的 5 拍。
   填充模块吃边缘、边缘只有 M3 那条支路有（已在延迟 4），4+3=7 是物理下限 —
   ⇒ M7 只能是"逐档延迟"，判据 A 因此改成**逐帧**判（M7 帧 8 拍、其余 5 拍）。
4. **掩蔽**：M7 档**不叠顶层掩蔽**（`w_masked_dat` 对 M7 直通）。
   两条理由：(a) u_rf 自带同口径掩蔽（前 3 行 + 每行第 0 拍）；(b) 顶层掩蔽对齐在延迟 4 拍，
   与 M7 的 7 拍不同拍，硬叠会把掩蔽区整体挪 3 拍（每行 12 像素）。
   ⇒ M7 帧掩蔽区输出**黑**，其余档位仍是"掩蔽期输出原图"。判据 M③ 单独钉死这条语义。

## ④ 本次唯一的非预期发现（已修，留作回归）

**现象**：接入后 M7 帧 1,051 拍不符，失配行恰好是 `8..15 / 24..31 / 40..47 / 56..63`。

**定位链**（四步，每步都有独立证据）：

1. 探针 TB（`sim\_m7dbg\tb_m7_probe.v`，**调试用，不进交付判据**）打出 u_rf 的输入流/膨胀/inside；
   `sim\_m7_probe_cmp.py` 按拍序对拍 → **填充模块的输入流本身就有 62 拍与参考不同**。
2. 62 拍全是**每行的第 0 拍**：RTL 给 `####`（4 个像素全算边缘），金标准给 `#...`。
   根因 = `alg_sobel_96` 的窗口在"窗口不可信拍"上**横跨行/帧边界**，输出的是**未定义值**；
   M3 档位上看不出来，因为顶层掩蔽在这些拍上把结果换成了原图。
3. 那 62 拍被填充模块自己的掩蔽挡住了（第 0 拍输出黑）——**但 3×3 膨胀会往左多吃一个像素**：
   第 1 拍（列 4..7）的膨胀窗口含列 3，正是第 0 拍的未定义值 ⇒ 每行第 4 列冒出一个假边缘
   ⇒ 填充的 inside 翻转位置整体错位 ⇒ 1,051 拍错。
4. 反证：把 **RTL 实测的输入流**（含那 62 拍）喂给参考填充模型 → 与 RTL 输出 **0/2560 拍不符**
   ⇒ 填充模块本身完全正确，问题 100% 在"喂进去的流没定义"。`sim\_m7_dbg_frame.py` /
   `_m7_dbg_inside.py` / `_m7_probe_cmp.py` 是这一段的证据脚本。

**修法**：M7 支路的阈值输出再与 `r_mask_d`（就是顶层那套、对齐在延迟 4 拍的窗口可信信号）相与，
把这些拍**明确声明为黑**；参考模型同口径（`m7_input_mask()`）。
**回归钉死**：变异 `M7 输入不与 r_mask_d 相与` → B(1060) 报红。

⚠ **另一条路（本次没走，留给你定）**：把 `win3x3_96` 在第 0 拍的左邻补零，
让 M3 流**处处有定义**（与金标准完全一致），那样 M7 支路就不需要这一层掩蔽。
代价是要动已验收模块 + 3 副本 + 它自己的判据；本次按"最小改动、不碰已验收模块"处理。

## ⑥ 与任务书不符 / 我认为任务书写错了的地方

1. **"加一级硬阈值就行"不够**：阈值之外**还必须**用窗口可信信号挡住未定义拍（见 ④）。
   任务书假设"M3 的信号要么是纯二值、要么是提亮图，二值化即可"，
   实际还有第三种情况：**窗口不可信拍上 M3 输出的是未定义值**，而填充的膨胀会跨拍吃它。
   这一条如果你只按任务书做，会得到 1,051 拍错且极难定位（失配行还是周期性出现的）。
2. **"M7 的输出比 M0/M1 晚（行位移 + 3 拍）"里的"行位移"要分开算**：
   相对**原图**，M7 一共下移 **2 行**（M3 自己的 1 行 + 填充模块契约的 1 行），
   相对 **M0/M1 的输出帧**才是 1 行；拍延迟才是 +3。任务书把两者写在一起，
   按字面理解会做成"shift1"而不是"shift2"（本报告的判据都用 shift2 = `_shift1` 两次）。
3. **"模块内部已经做了掩蔽（3 行 + 每行第 0 拍），所以 alg_top 里这一档不要再叠行掩蔽"**：
   我按"**M7 档整条顶层掩蔽都跳过**"实现（掩蔽区输出黑，不是原图）。
   如果你的本意只是"不要再往 u_rf 的输入上叠掩蔽"（保留顶层"掩蔽期输出原图"），
   那就需要再补一条延迟 7 拍的原图通路 + 一条延迟 7 拍的掩蔽（96×3 DFF + 3 DFF），
   并且掩蔽语义会和别的档位一致 —— 但**任务书这句话字面上是让我跳过**，我按字面做了。
4. **档位编号与项目文档冲突**：`doc_describe\分层实施计划_20260917.md` 与
   `osd_mixer.v` 第 5 节的注释都写 **M7 = 直方图均衡（HISTEQ）**，任务书把 M7 给了区域填充。
   OSD 只显示 "M7" 两个字符，硬件上不冲突；但**文档/注释现在与 RTL 不一致**，建议你统一。
5. **任务书点名要抓的变异"按键循环上限只到 M6"在小尺寸里原本是抓不到的**：
   旧的小尺寸档位表 `I_mode_set=1` 恒 1、逐帧强制指定档位 ⇒ **按键路径根本没被激励**，
   这条变异会是"dump 与基线逐字节相同"的空操作（= 无效变异）。
   我把小尺寸的**第 8 帧改成走按键路径**（前 7 帧仍用 `I_mode_sel`，帧 6 内按 7 下键 ⇒
   `r_mode_hold=7`）。这样才能真正抓到它（实测 B/D 各 2560 报红）。
   这是对测试框架的**语义扩展**，任务书没提，我按"变异必须可抓"的目标做了。
6. **`_shift1()` 只对"过窗口"的档位成立**：M5（颜色检测）与 M6（帧差）都没有整体位移，
   M7 是**两次** `_shift1`。任务书说"M2/M3/M4 都这么比"是对的，但别把它推广到全部档位。
7. **"全尺寸由我统一跑"的提醒**：你那套 12 帧时序里没有 M7 帧，所以
   (a) 判据 **M 与 L 都会是 0 次检查**（两条都会打警告说明覆盖在小尺寸；
   `L` 在本次改动之前就已经是 0 次，不是新问题）；
   (b) 若你要在 1280×720 下验证 M7，需要给那套表加一帧 M7（改 `MODE_SCHED` 与 TB 的档位表，
   两者必须同改，否则判据 D 会报）。
8. `run_full_algtop.ps1` / `run_l1_full.ps1` / `run_bubble.ps1` / `run_all_alg_top.ps1` 的
   编译清单都已加上 `alg_region_fill_96.v` —— **不加的话你的全尺寸跑会直接编译失败**
   （TB 例化了 alg_top，alg_top 例化了 u_rf）。
